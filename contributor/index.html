Open Score DeskChoose a project score

Drafts are saved on this device. Shared reports and proposals are saved by the project service only after you submit and receive a receipt. Production sharing needs the project owner to activate that service.

Selected work

Open this work’s shared page

When sharing is activated, Score Desk assembles the exact printed source, LilyPond and rendering. If the source library is unavailable, it asks for only the original printed PDF and checks that file automatically.

Report an error

Open a work. Choose New finding and type a note, or draw a highlight. Select Submit findings and sign in. One finding is enough.

The receipt means your report is saved in the project. You can leave; no full-score review, AI work or pull request is required.

Review this score

Compare any part, or every page and system, of a score with the printed source. Submit your findings and actual scope, or explicitly declare No errors found in the reviewed scope.

A clean review leaves other people’s findings open. Reviewing does not require changing the music and does not by itself verify the work.

Help fix reported errors

Choose a work with outstanding findings and select Get correction package. Download the ZIP, attach it to your chosen AI, and paste the supplied instructions.

Choose Return AI response when it is ready. Your contribution ends there. Another person checks the proposed corrections.

Review proposed fixes

Open a shared proposal and compare its rendering with the printed source. Original reports, historical context, proposed LilyPond and decision history stay available.

Check any selected finding: Looks correct, Still needs correction, or Needs clarification. Other findings remain for other people. Applying a reviewed correction to the project is a separate maintainer step.

What the status means

  • Saved locally: a draft on this browser and site, available without signing in.
  • Submitted to the project: the shared service acknowledged the write and issued a stable receipt.
  • Awaiting review: an AI response is a proposal that has not changed the published score.
  • Applied to the project: an authorized maintainer recorded the reviewed candidate at the canonical repository revision.

Sign in with GitHub when submitting. An optional typed name is not authenticated identity. Complete coverage, an appointed verifier and approval of the exact eligible revision are required for human verification.

Existing packages and local drafts

Open package, the brush editor, text-only findings, local saved reviews and recovery ZIPs remain available. Download a recovery package before changing browser profiles or origins; unsubmitted drafts remain local.

A shared AI response can be opened from a fresh browser because the project retains its immutable original task. Legacy local tasks still need their original retained baseline or a supported portable backup; validation is never bypassed.

Use the optional agent / maintainer handoff on a submitted report or reviewed proposal to prepare a traceable repository contribution. Ordinary reporting has no PR requirement.
