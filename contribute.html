Three agent runs, then a human check

Steps 1 and 2 are independent transcriptions by different agents. Neither reads the other's work before submitting its own. Each run needs an initial encoding and at least one targeted correction pass after inspecting the render; a third validation pass is preferred.

Agents must read the printed edition visually and enter LilyPond directly. Optical music recognition, OCR-to-score tools, MusicXML or MIDI conversion, and existing digital transcriptions are not allowed.

At Step 3, a third agent compares both LilyPond files with the printed edition, resolves disagreements, and produces score.ly. It remains marked “Needs proofreading” until a human checks it.

Four ways to help in Score Desk

Choose a work in Score Desk and open Project contributions. The shared service, once activated by the project owner, supplies the files and keeps reports available across people and devices. Reading and drafting are open; shared submissions use GitHub sign-in.

  1. Report an error. Type a finding or draw a highlight and choose Submit findings. One finding is enough. A receipt confirms it reached the project. You are done.
  2. Review this score. Choose a partial or whole-work scope. Submit findings or explicitly declare No errors found in the reviewed scope. You do not need to change any music. Your clean review does not close anyone else's findings.
  3. Help fix reported errors. Choose Get correction package. Download its ZIP, attach it to your chosen AI and paste the supplied instructions. Choose Return AI response when it finishes. Another person can check the proposal.
  4. Review proposed fixes. Open a proposal, compare it with the print, and record Looks correct, Still needs correction, or Needs clarification for any findings you checked. Others can finish the remainder.

Saved locally means this browser has a draft. Submitted to the project requires a shared receipt. Awaiting review means a returned proposal exists. Applied to the project requires the reviewed candidate to reach the canonical repository revision. These are separate events.

If the service is not configured, Score Desk clearly says shared submission is inactive; keep using local review and recovery ZIPs. Existing Discussion reports remain available. A contributor can link and explicitly structure a Discussion report while retaining its stated author and original URL.

For publication, a maintainer or coding agent uses the exact reviewed candidate and provenance to prepare a correction PR, or a review-only provenance contribution with unchanged LilyPond. Human verification requires an eligible Step 3 score, complete coverage, an authorized identified verifier and approval of the exact revision. No report, clean declaration or AI assertion grants verification.

Pull request details

Every transcription pull request must identify its step, the exact model, and the printed source:

Step: 1/3
Model: provider/exact-model-id
Source: https://example.org/printed-edition

A human verification pull request instead identifies the proofreader with Review: human and Proofreader: @github-name, plus the printed source URL.

Also state the scope, LilyPond version, pages compared, correction pass, unresolved readings, and suspected source mistakes. The checks compile every score, verify the metadata and catalog, and reject a transcription pull request when the provenance annotations are missing. A merge rebuilds the site.
