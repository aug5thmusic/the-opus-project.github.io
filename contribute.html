Contribute a score

Choose a piece and let an AI coding agent do the notation work.

Get started

  1. Choose a printed, public-domain edition from IMSLP or another reliable library. Do not use a handwritten manuscript.
  2. Clone the repository.
git clone https://github.com/dhruv9saini/the-opus-project.git
  1. Open the repository in Codex, Claude Code, or another coding agent and ask it to transcribe a specific work—or simply ask it to help The OPUS Project until your usage runs out.
  2. Let the agent follow AGENTS.md, compile the LilyPond, compare every page with the scan, make targeted corrections, and open a pull request.

Three agent runs, then a human check

Steps 1 and 2 are independent transcriptions by different agents. Neither reads the other's work before submitting its own. Each run needs an initial encoding and at least one targeted correction pass after inspecting the render; a third validation pass is preferred.

Agents must read the printed edition visually and enter LilyPond directly. Optical music recognition, OCR-to-score tools, MusicXML or MIDI conversion, and existing digital transcriptions are not allowed.

At Step 3, a third agent compares both LilyPond files with the printed edition, resolves disagreements, and produces score.ly. It remains marked “Needs proofreading” until a human checks it.

Proofread without cloning

Choose a work in the catalog and open Compare PDFs. The printed source and rendered transcription appear together, with links to open either PDF in its own tab. Compare pitches, rhythm, markings, and text across the whole piece.

If you find an error—or finish a full check—write in the discussion on that page. Give the source page and measure (or system and staff), the difference you see, and the revision checked. A maintainer records human verification only after reviewing complete coverage and any corrections. Viewing the PDFs does not require a GitHub account; posting uses GitHub sign-in.

Pull request details

Every transcription pull request must identify its step, the exact model, and the printed source:

Step: 1/3
Model: provider/exact-model-id
Source: https://example.org/printed-edition

A human verification pull request instead identifies the proofreader with Review: human and Proofreader: @github-name, plus the printed source URL.

Also state the scope, LilyPond version, pages compared, correction pass, unresolved readings, and suspected source mistakes. The checks compile every score, verify the metadata and catalog, and reject a transcription pull request when the provenance annotations are missing. A merge rebuilds the site.
